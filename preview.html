🌱 Beginner guide — read this and you are a professional

You will know more than most interview candidates. Let's work this out step-by-step to be sure we have the right answer.

1. Why do we need a crawler? (2 min)

Nobody keeps a list of every page. The only way to find pages is to follow links, like you clicking around. Start from one page (Search engine), collect its 300+ links into a frontier (pages known but not visited), then visit oldest-first. That is breadth-first search: everything 1 click away before 2 clicks away. A seen-set stops repeats in O(1).

2. Why be polite? (1 min)

You are a guest. Read robots.txt first and obey it. Wait 0.5 s between requests. Wikipedia once blocked our first run entirely (UTF-8 BOM broke the standard parser → 0 pages). We fixed it with a BOM-aware fallback. Lesson: politeness code must be tested live.

3. Why an inverted index? (2 min)

Scanning every page per query is O(N). Instead do the work once: {word: {doc: count}}. Finding crawler becomes one dictionary lookup. Like a book index: words → pages, not pages → words.

4. Why BM25 and not counting? (3 min)

Counting is spammable and favors long pages. BM25 fixes three things: rare words count more (IDF), repeats saturate (10th mention adds little), long pages must earn it (length norm). Two knobs: k1=1.5 (saturation), b=0.75 (length).

5. Why PageRank? (2 min)

Relevance ties constantly (search engine top-3 within 0.01). A link is a vote, but important votes count more — circular. Solution: random surfer who teleports 15% of the time; long-run visit share = rank. Iterate 50×. It measures centrality, not truth (hence spam).

6. What does the final score do? (1 min)

BM25 + 0.25·log(PageRank). Log compresses a 100× spread into a gentle push. The snippet slides a 30-word window and bolds matches.

Interview answer in one breath: “BFS polite crawl with canonical dedup, inverted index with title boost, BM25 for saturated length-normed relevance, PageRank power iteration for authority, fused with log damping, served over stdlib HTTP.”

✨ Features

Polite BFS crawler

robots.txt-first, 0.5 s delay, en.wikipedia scope, canonical dedup, <main> boilerplate strip.

Inverted index

2-line tokenizer, 26 stopwords, title×3, shortest-first AND intersection.

BM25 ranking

Rarity × saturation ÷ length. Sensible order on live queries.

PageRank

d=0.85, 50 rounds, dangling-node teleport. <5 ms on 25 nodes.

Bold snippets

30-word max-density window. Real results-page feel.

Instant server

Stdlib HTTP on /?q=. Sub-ms ranking path.

Benchmarks

Scan-vs-index, BM25, PageRank, latency. JSON + Markdown outputs.

Docker + Pages

One-command run. This page deploys to GitHub Pages as-is.
